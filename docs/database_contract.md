# Database Contract

Документ описывает текущий контракт общей PostgreSQL-базы между ArtFlowBot и ArtFlowWeb.

Схема проверена по архиву **ArtFlowBot v1.1**, загруженному 11 июля 2026 года. Источник: `database.py`.

## 1. Правила контракта

- ArtFlowBot и ArtFlowWeb используют одну PostgreSQL-базу.
- ArtFlowBot может читать и изменять данные в рамках своей бизнес-логики.
- ArtFlowWeb получает только чтение публичных таблиц.
- ArtFlowWeb не импортирует `database.py` из репозитория бота.
- Изменения схемы выполняются отдельными миграциями.
- Текущие поля нельзя удалять или переименовывать незаметно.
- Новые поля сначала добавляются как совместимые, затем подключаются в боте и на сайте.

## 2. Публичные таблицы

### `competitions`

Назначение: хранит конкурсы, которыми администратор управляет через ArtFlowBot и которые должен показывать ArtFlowWeb.

#### Текущая схема

| Поле | PostgreSQL-тип | Nullable | Значение по умолчанию | Используется ботом | Нужно сайту |
|---|---|---:|---|---:|---:|
| `id` | `SERIAL` / `INTEGER` | Нет | Автоматически | Да | Да |
| `name` | `TEXT` | Да | — | Да | Да |
| `description` | `TEXT` | Да | — | Да | Да |
| `document` | `TEXT` | Да | — | Да | Частично |
| `date` | `TEXT` | Да | — | Да | Частично |
| `place` | `TEXT` | Да | — | Да | Частично |
| `price` | `TEXT` | Да | — | Да | Да |
| `create_at` | `TIMESTAMP` | Да | `CURRENT_TIMESTAMP` | Нет | Возможно |

#### Текущее поведение ArtFlowBot

- список загружается функцией `get_all_competitions()`;
- сортировка выполняется по `id ASC`;
- фильтра «актуальные» в SQL нет;
- конкретный конкурс запрашивается строковым идентификатором `competition_<id>`;
- `document` передаётся в `open(...)` как локальный путь;
- администратор добавляет и изменяет только `name`, `description`, `document`, `date`, `place`, `price`.

#### Ограничения для сайта

| Требование сайта | Текущее состояние | Вывод |
|---|---|---|
| Показывать только нынешние конкурсы | Нет даты типа `DATE` и признака публикации | Нельзя надёжно определить актуальность |
| Фильтр по городу | Город смешан с `place` | Нужен отдельный `city` |
| Фильтр по направлению | Направления не хранятся | Нужны структурированные данные |
| Срок подачи заявки | Поля нет | Нельзя показать и вычислить статус регистрации |
| Афиша | Поля нет | Нужна публичная ссылка на изображение |
| Положение на сайте | Хранится локальный путь | Нужна публичная ссылка или объектное хранилище |
| Красивый URL | `slug` отсутствует | Можно начать с `id`, но `slug` желателен |
| Черновик или публикация | Признака нет | Все записи считаются доступными |

#### Предлагаемые совместимые поля для MVP

Эти поля пока являются архитектурным предложением. Перед миграцией их нужно утвердить.

| Новое поле | Тип | Для чего нужно | Обязательность при добавлении |
|---|---|---|---|
| `slug` | `TEXT UNIQUE` | Читаемый URL страницы конкурса | Можно добавить nullable |
| `short_description` | `TEXT` | Краткий текст карточки | Nullable |
| `event_date` | `DATE` | Сортировка и определение нынешних конкурсов | Nullable на этапе миграции |
| `application_deadline` | `DATE` | Срок приёма заявок и статус регистрации | Nullable на этапе миграции |
| `city` | `TEXT` | Фильтр и отдельное отображение города | Nullable на этапе миграции |
| `directions` | `TEXT[]` | Фильтр по направлениям | Nullable или пустой массив |
| `image_url` | `TEXT` | Публичная афиша | Nullable |
| `rules_url` | `TEXT` | Публичное положение | Nullable |
| `is_published` | `BOOLEAN` | Скрытие черновиков и старых записей | `FALSE` по умолчанию |
| `updated_at` | `TIMESTAMP` | Контроль обновления контента | Nullable или текущее время |

#### План совместимости

1. Добавить новые поля, не меняя текущие `date`, `place`, `document`.
2. Существующий бот продолжает работать без изменений.
3. Добавить заполнение новых полей в админ-панель отдельным этапом.
4. Сайт сначала использует новые поля и безопасные fallback-значения.
5. Удаление старых полей не входит в MVP.

### `faq`

Назначение: хранит частые вопросы и ответы, которыми администратор управляет через ArtFlowBot.

#### Текущая схема

| Поле | PostgreSQL-тип | Nullable | Значение по умолчанию | Используется ботом | Нужно сайту |
|---|---|---:|---|---:|---:|
| `id` | `SERIAL` / `INTEGER` | Нет | Автоматически | Да | Да |
| `question` | `TEXT` | Да | — | Да | Да |
| `answer` | `TEXT` | Да | — | Да | Да |
| `create_at` | `TIMESTAMP` | Да | `CURRENT_TIMESTAMP` | Нет | Возможно |

#### Текущее поведение ArtFlowBot

- FAQ сортируется по `id ASC`;
- администратор может добавлять, изменять и удалять записи;
- все записи отображаются пользователю;
- FAQ общий для всех конкурсов.

#### Необязательные улучшения позднее

| Поле | Тип | Назначение |
|---|---|---|
| `display_order` | `INTEGER` | Ручной порядок вопросов |
| `is_published` | `BOOLEAN` | Черновики и скрытые вопросы |
| `category` | `TEXT` | Группировка общих и конкурсных вопросов |

Для первого MVP сайт может читать текущую таблицу `faq` без её изменения.

## 3. Приватные таблицы

ArtFlowWeb не должен иметь к ним доступ.

| Таблица | Назначение | Доступ сайта |
|---|---|---|
| `ArtFlow_bid` | Заявки пользователей | Запрещён |
| `participants` | Участники заявок | Запрещён |
| `users` | Пользователи, запустившие бота | Запрещён |
| `admins` | Администраторы | Запрещён |

## 4. Рекомендуемые права PostgreSQL

Планируемая роль:

```text
artflow_web_user
```

Разрешения:

```text
SELECT ON competitions
SELECT ON faq
```

Запрещены:

```text
INSERT
UPDATE
DELETE
SELECT ON ArtFlow_bid
SELECT ON participants
SELECT ON users
SELECT ON admins
```

## 5. Deep-link контракт

Формат параметра:

```text
competition_<integer id>
```

Пример:

```text
competition_7
```

Полная ссылка:

```text
https://t.me/BOT_USERNAME?start=competition_7
```

Бот обязан проверить:

- наличие параметра;
- точный префикс `competition_`;
- числовой ID;
- существование конкурса;
- возможность подачи заявки;
- отсутствие доступа к скрытому конкурсу.

Текущий ArtFlowBot v1.1 этот параметр ещё не обрабатывает.
